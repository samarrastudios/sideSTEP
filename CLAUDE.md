# sideSTEP - project notes for Claude Code

Windows utility: STEP/STP files get real thumbnails and a spinnable preview pane in File Explorer, and open in a lightweight native 3D viewer with model tree, pan/zoom/rotate, measure and explode. The viewer is meant as the quick look: it becomes the default app for STEP files and hands off to the owner's CAD package with one click. Owner: Adrian. Built ground-up; comparable product is "STEP Explorer Preview" on the Microsoft Store.

## Decisions already made
- All native C++17. Geometry kernel: OpenCASCADE via vcpkg manifest (`vcpkg.json`), triplet `x64-windows-static-md`.
- Viewer is Qt 6 Widgets + OCCT's AIS/V3d viewer (not web tech). Qt comes from vcpkg (`qtbase`, minimal features, same static triplet), so the viewer is one self-contained exe.
- The shell DLL stays free of Qt: the preview pane is plain Win32 + OpenGL 1.1 on the `core/` triangle mesh.
- Hand-off: the viewer's "Open in <app>" button launches a CAD app the user picks inside sideSTEP (File > Open with: apps Windows lists for STEP, or any exe). Stored in `HKCU\Software\sideSTEP\sideSTEP\externalApp`.
- The 3D view background is Paper by default (black powder-coat parts vanish on Graphite); the window chrome is Graphite. View > Light background switches it.
- Milestone order: (1) Explorer thumbnails, (2) viewer, (3) preview pane + property columns, (4) installer.
- GitHub repo: https://github.com/samarrastudios/sideSTEP (remote `origin`, branch `main`).
- Distribution: source on GitHub, with a downloadable setup `.exe` attached to GitHub Releases. No Microsoft Store, no MSIX. Per-user install (no admin) preferred. Signing is optional and undecided; unsigned builds trigger a SmartScreen warning.
- `core/` must stay free of Windows and Qt headers; `core/thumb_core.h` must stay free of OCCT types.
- Per-user (HKCU) COM registration for development; no admin.
- Once the viewer is installed, sideSTEP should be the default app for opening STEP files (.step/.stp/.p21). The installer registers a ProgID + file type association in the registry; Windows does not let an app take the default silently (UserChoice is hash-protected), so the user confirms once via "Open with > Always" or Settings > Default apps. Belongs to milestones 2 and 4, not the thumbnail work.
- Branding: `assets/brand/` is the full brand packet; read `assets/brand/BRAND.md` before making anything user-facing. Use it everywhere it applies: installer dialogs (icon, lockup, Graphite/Paper/Signal orange palette), the exe/DLL/viewer icons (`icon/sidestep.ico` via an `.rc`), the README header, and the GitHub avatar and social preview. Follow its rules (no recoloring, gradients or shadows; "sideSTEP" in prose, `sidestep` in code).
- Credit line for the installer, About box and GitHub: "Created by Adrian Samarra. Open source, for Windows, released on GitHub."
- The project name lives in `CMakeLists.txt` (`APP_NAME`, `APP_DISPLAY_NAME`).

## State (2026-11-16, version 0.2.0)
- Builds clean on Windows: Build Tools 2022 (MSVC 19.44), vcpkg baseline pinned in `vcpkg.json`, OpenCASCADE 8.0.1, Qt 6.11.3, triplet `x64-windows-static-md`. First build: OCCT ~55 min, Qt ~50 min (vcpkg builds a full host copy of Qt for moc/rcc as well as the minimal target copy). Later builds take seconds to a couple of minutes.
- **Milestone 1 (thumbnails):** confirmed in Explorer on the owner's real files (2026-11-15).
- **Milestone 2 (viewer), built 2026-11-16:** `viewer/` -> `sideSTEP.exe`. Loads on a worker thread with progress and cancel; model tree with show/hide checkboxes, tree <-> 3D selection sync; orbit/pan/zoom, fit, standard views, perspective, edges; hide/isolate/show all; measure (two picks: distance, deltas, angle, hole centre-to-centre, mm + in); explode slider (radial from the assembly centre); Page Up/Down through the STEP files in the folder; drag and drop; "Open in <app>" hand-off; About box. Verified by automated dumps on the samples and the owner's assemblies (6, 22 and 31 MB).
- **Viewer tools, added later on 2026-11-16 at the owner's request:** icon toolbar (`icons.cpp`, drawn in code, no SVG module); measure tool with modes (distance, point to point, length/diameter, angle, overall size), kept measurements with in-view labels, list, copy and units (`measure_tool.cpp`); section view on X/Y/Z with slider, flip and filled cut faces (`section_tool.cpp`, an OCCT clip plane with capping); display modes (shaded with edges, shaded, wireframe, X-ray); right-click menu; tree filter; fit selection. The tools were checked by automated dumps; the right-click menu and the tree filter have only been compiled, not exercised.
- **Viewer redesign, 2026-11-16 (later):** the owner brought a hand-off brief and an approved design mock from a browser-based 3D viewer they had built in another project, and wants sideSTEP to feel like its grown-up desktop sibling. Built to that design: part tree with eye toggles, counts and search; floating bar of nine buttons at the bottom of the model; tool settings in a pill at the top; view cube with home; readout strip; one tool at a time; step-by-step Esc; display styles as one list; section box; parts list; snapshot; full screen; show only (fades the rest); animated camera turns; double-click zoom; mouse presets; sizes in the file's units first. Keys follow the brief (Ctrl+1-7 and Shift+1-7 both work).
  - sideSTEP keeps its own brand: Signal orange marks the active tool. Nothing was copied from that other project (code, icons, strings, house style); the icons are redrawn in `icons.cpp`. It belongs to someone else and sideSTEP is public and MIT-licensed, so keep it that way unless the owner says otherwise. Where the brief and mock live is in the assistant's private memory, not in this repo.
  - The floating controls (`hud.cpp`) are a separate frameless translucent window kept over the 3D view, masked to its controls so clicks elsewhere reach the model. Reason: the 3D view is a native OpenGL window and Qt cannot composite translucent widgets over it. The alternative, rendering OCCT inside a QOpenGLWidget, needs Qt rebuilt with its `opengl` feature (~20 min) and a rewrite of `occ_view.cpp`; worth it if the overlay window ever shows lag or z-order trouble.
  - The view cube is painted by Qt (`view_cube.cpp`) because OCCT's own AIS_ViewCube needs FreeType for its labels.
  - Not built from the brief yet: dragging the section plane or box faces in the view, snapping to edge midpoints, light/dark following the system theme, IGES, recent files, and Esc closing the window as the last step (left out on purpose for a desktop app; ask the owner).
  - Checked by off-screen dumps: layout, section, section box, measure, explode, display styles, standard views with the camera animation. Not exercised: eye toggles, show only, parts list, snapshot, full screen, the Esc ladder, view cube clicks, mouse presets, double-click zoom.
- **Later the same day, from the owner's first hands-on feedback:** view cube redrawn (lit faces, seams for the edge and corner zones, floor shadow, round home chip with a solid house; labels are drawn as outlines because skewed text picks up ClearType colour fringes); explode made smooth and grouped (the slider sets a target and a 60 Hz timer eases to it; each item moves away from its parent assembly's middle and carries its children; All/X/Y/Z direction); a key light fixed to the model that casts shadow-mapped shadows plus a camera light and ambient fill, Phong shading; perspective in the Display list (O); six mouse styles with a switcher on the readout strip and a reverse-scroll switch.
  - Explode performance lesson: on the 1,541-part file a moving frame cost 50-100 ms, and almost all of it was `V3d_View::FitAll` (it re-measures every object), not moving the parts (2 ms). `OccView::fitPointsQuick` does the fit with arithmetic on the camera instead; a frame is now ~16 ms. While parts move they are placed with `SetLocalTransformation`; `ctx->SetLocation` (which also updates picking) runs once at rest.
  - The wheel-direction defaults per mouse style are from memory of those programs (only SolidWorks is set to reversed) and have not been checked against them.
- The owner made sideSTEP the default for .step on 2026-11-16. Windows then stops listing the previous default as "recommended", so the hand-off list also offers known CAD exes from the full handler list (`IsKnownCadApp` in `open_with.cpp`).
- Windows blocks all preview handlers for files carrying the internet-zone mark ("could harm your computer", with a Preview anyway button). The owner's Downloads STEP files were marked, and so are the files on his Google Drive (G:): Drive for desktop presents itself as FAT32 without named streams and maps to the local zone, yet every file carries `Zone.Identifier` with ZoneId=3. (An earlier note here said G: was unaffected; that was wrong.) Not something the handler can bypass. The owner asked for it to be gone for every file type sideSTEP opens, so `sideSTEP.exe --watch` (`viewer/unblock.cpp`) removes the mark from .step/.stp/.p21 files only: it watches every fixed drive, sweeps existing files on NTFS drives (user profile first), follows open File Explorer windows and unblocks the STEP files they list (this is what covers Google Drive and the Home / search lists, verified on a real shared drive: marks cleared within seconds of opening the folder), handles read-only files, and `--register` adds it to the HKCU Run key. Tested in a scratch folder (marks cleared in seconds, other file types untouched, ~13 MB). Claude Code's safety check sometimes refuses to let the assistant run `scripts\install.ps1` because of this autostart helper; when that happens, the owner runs it. Installed and running on this machine since 2026-11-16. It is opt-out for other users, at the owner's decision: `sideSTEP.exe --helper-on` / `--helper-off` (the off switch signals the running helper to exit), a checkable item in the viewer's File menu, `scripts\install.ps1 -NoPreviewHelper`, and a ticked-by-default task in `installer\sideSTEP.iss`. `--register` no longer touches the helper. In PowerShell never `Start-Process -Wait` on `--helper-on`: it also waits for the helper, which never exits.
- **Setup program, 2026-11-16:** `scripts\package.ps1` builds `build\installer\sideSTEP-Setup-<version>.exe` from `installer\sideSTEP.iss` (Inno Setup 6.7.3, installed per-user via winget with the owner's go-ahead). Per-user, no admin; ships msvcp140, msvcp140_1, vcruntime140 and vcruntime140_1 beside the app instead of rebuilding everything with the static runtime; one ticked-by-default task for the preview helper. Tested silently on this machine: install, every registration, thumbnail through the shell, preview through prevhost, viewer run, then uninstall (everything removed) and reinstall. The wizard pages themselves (including the checkbox) have not been looked at, and it has not been tried on a second PC.
- This machine now runs the setup-program install, not the `install.ps1` one. Running `install.ps1` again would add a second Installed-apps entry.
- **Preview pane, built 2026-11-16:** `shellext/preview_handler.cpp` in the same DLL as the thumbnails. Drag spins, wheel zooms, right-drag pans, double-click resets; sideSTEP mark bottom-right. Verified with `sidestep-previewtest` in-process (images) and through prevhost.exe (debug log shows the DLL loading, DoPreview succeeding and a multisampled OpenGL format). Not yet looked at in the real Explorer pane.
- File type: `sideSTEP.exe --register` writes the ProgID `sideSTEP.step`, OpenWithProgids for .step/.stp/.p21 and the Default-apps capability (HKCU). The owner still has to choose sideSTEP once; on this machine the current default is FreeCAD.
- Viewer load times here: 31 MB / 1541 parts ~10 s, 22 MB / 679 parts ~10 s, 6 MB ~3 s, samples well under 1 s. OCCT's transfer step dominates and is single-threaded.
- Thumbnail times measured with the CLI on the same files: 14 s (31 MB), 28 s (22 MB), 21 s (50 MB), 3.4 s (6 MB).
- Hardware exceptions inside OCCT are now caught in the shell DLL (`SafeLoadStep`, `SafeRenderThumbnail`); the viewer catches only C++ exceptions.
- Known conflict: when the Store app "STEP Explorer Preview" (AelyoSoftworks.STEPExplorerPreview) is installed, its packaged thumbnail handler wins for `.step`/`.stp`/`.p21` even though `AssocQueryString` resolves to our CLSID. Other users will hit this; only a packaged handler of our own could compete on equal terms. Expect the same for the preview pane.
- The shell DLL meshes single-threaded (OCCT's `OSD_ThreadPool` static destructor hangs a DLL host at exit). The viewer and CLI mesh in parallel.
- Opt-in debug log: `HKCU\Software\sideSTEP` value `DebugLog` = file path.
- Testing tip: Explorer caches thumbnails per file, including failures; copy the file to a new name to force a fresh request.
- Testing the viewer without a person: `sideSTEP.exe file.step --dump out.png [--explode 0-100] [--display 0-3] [--section x,0.5] [--measure-mode 0-4] [--clicks "x,y;x,y"]` runs off-screen, writes the 3D view, `out.png.window.png` (whole window) and `out.png.txt` (measurements and the hand-off app list), then quits. `--clicks` are measure picks as fractions of the view; measure modes are numbered as in `MeasureTool::Mode`.
- Testing the preview handler: `sidestep-previewtest <dll | registered> file.step out.png [seconds] [dragPixels]`.

## Conventions
- A failed thumbnail must fail quietly (return an error HRESULT); never show UI or crash the host.
- Rebuilding while registered: `build.ps1` kills any dllhost holding the DLL.
- Registry paths in C++ are raw string literals (`LR"(...)"`). An unknown escape (MSVC C4129) is a compile error in the viewer and shell DLL: a dropped backslash once made `--register` write junk keys at the root of HKCU while reporting success.
- Never capture the owner's screen to test; use the off-screen `--dump` and `sidestep-previewtest` routes.
- When generating source files from a shell heredoc or a script, check backslashes survived (prefer the editor's own file-writing over heredocs for C++ with escapes).
